## Observed weakness and bounded successor
Current `stock_original_emulator_probe.launched` requires the same launcher component class to appear in a resumed-Activity record. A valid Android `activity-alias` launches a different target class, and a genuine app may transition to another activity. A running process alone is insufficient, and it is **not proved** that this exact alias/transition caused the observed failure.

The correction shall distinguish the exact launcher from a different **same-original-package** globally top-resumed activity. It shall read the system's real global `ResumedActivity`/`topResumedActivity` and visible-activities snapshot, require a consistent *single original-package component* to qualify UI, and reject absent/malformed/foreign/ambiguous/old-stack-only or crash states. All raw system activity/window output is private ephemeral only. Publish only stable enum/boolean diagnostics; never raw OEM class names, activity records, package-manager output, logcat, screenshot, accounts, secrets or private APK bytes. Package SHA pin, original signature, serial/API37 disposable guest, offline isolation, no retry and no physical-device gates remain mandatory. Positive, negative, alias, handoff, cross-package, non-top-stack and redaction regressions plus exact-SHA public source/android CI must pass. No protected workflow dispatch or merge by chat; an owner later reviews and authorizes merge, then manually dispatches owner-only protected test on new main.
